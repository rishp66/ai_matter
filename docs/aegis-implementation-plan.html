AEGIS · MVP Implementation Plan

From forked repo to working demo

Build order for the Mattermost × GraphN personal agent. Sequenced so an end-to-end loop works before any React is touched, and so the team can parallelize after the first phase.

Start state: Mattermost fork cloned Backend: GraphN account + CLI Target: one demo user, one channel Fail-safe: always DRAFT

Phases

P0  Boot the fork P1  Bot + bridge echo P2  GraphN: KBs & workflows P3  The gate P4  Approval card P5  Loop prevention P6  Polish & webapp Config quick-ref Team split Demo script
Read first — the sequencing unlock

Native Mattermost message-attachment action buttons render on the stock fork UI. The whole approval loop (P1–P5) works with zero webapp changes — orchestration lives in a small bridge service. Forking the React webapp (P6) is polish, not a dependency. Don't start there.

P0  Boot the fork

Goal: the forked Mattermost runs at localhost:8065, you can log in and post, and you know which half is server vs webapp.

License gotcha

Forking obligates AGPL compliance and replacing the Mattermost name/logo per the trademark policy if you distribute or demo publicly. Fine for an internal hackathon — flag it before any public release.

DONE WHEN — you can log into your local fork and post in the demo channel.

P1  Bot + bridge skeleton (echo)

Goal: a bot hears messages and echoes a reply in-thread. No GraphN, no gate yet — prove the plumbing.

bridge — websocket loop (shape)
# authenticate, then react to posted events
ws.send({"seq":1,"action":"authentication_challenge","data":{"token":BOT_TOKEN}})
# on event: {"event":"posted","data":{"post":"{...json...}"}}
# parse post, ignore if post.props.from_bot, else reply in post.root_id or post.id

DONE WHEN — you post and the bot replies in-thread within ~1s.

P2  GraphN: KBs & workflows

Goal: two knowledge bases and two workflows, tested from the CLI, callable by the bridge via the gateway.

Why two physical KBs

Separate stores make provenance a yes/no fact ("did wf-private run / did kb-private return a chunk?") instead of an inference over labels. That's what makes the gate deterministic in P3.

DONE WHEN — a public query answers off kb-public and a private query pulls a kb-private chunk, both invokable by the bridge.

P3  The gate (public-first / escalate-and-lock)

Goal: the bridge decides AUTO_SEND vs DRAFT from retrieval provenance — and the auto-send path never loads private context.

bridge/gate — decision
# the auto-send compose never has kb-private in its window
pub = graphn.run(WF_PUBLIC, query, kb=["kb-public"])
if pub.grounded and pub.confidence >= CONF_MIN:
    return SEND(pub.text, provenance=pub.sources)
# escalate — verdict is DRAFT from here, no matter what
priv = graphn.run(WF_PRIVATE, query, kb=["kb-public","kb-private"])
return DRAFT(priv.text, reason=f"{priv.private_hits} private sources")

DONE WHEN — a public question auto-posts to the channel; a private question holds and never reaches the channel.

P4  Approval card

Goal: held drafts surface as an interactive card with Approve / Discard — using attachment actions, no webapp changes.

Known quirk

Updating an interactive post can drop its buttons. That's fine — every action resolves the card to a terminal, button-less state (Sent / Discarded), so buttons never need to survive an update.

DONE WHEN — a held draft shows Approve/Discard; Approve posts it to the channel and the card flips to a terminal state.

P5  Loop prevention

Goal: two agents can't talk each other into an infinite exchange.

DONE WHEN — two agents halt after ≤3 turns and never auto-loop.

P6  Polish & (optional) webapp fork

Goal: make it demo-clean. Only now is it worth touching React.

DONE WHEN — the end-to-end story runs clean on stage.

Team split

P0–P1 are the critical path — do them together. Once the bot echoes, the work forks cleanly and runs in parallel:

  • Track A — bridge / orchestration: P3, P4, P5. The bulk of the code.
  • Track B — GraphN: P2 — KBs, the two workflows, threshold tuning. Independent of the bridge once the gateway contract is agreed.
  • Track C — webapp (optional): P6 renderer + settings. Can start against a mocked custom_aegis_draft any time after P1.
Lock this contract early

The bridge↔GraphN interface (input shape, and that responses return sources + confidence) is the seam between Tracks A and B. Agree it in P2 so both can build against it.

Demo script (acceptance)

If these three run clean, the MVP is done:

  • 1 — Auto-send. Ask a public question in the channel → agent replies instantly. "It never had to ask me."
  • 2 — Held draft. Ask something needing private context → agent holds; show the DM card with the provenance line; Approve → it posts. "It caught that this touched my private notes."
  • 3 — Loop guard. Point a second agent at the first → it halts after N turns. "No infinite loops."
